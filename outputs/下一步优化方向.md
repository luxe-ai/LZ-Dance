# Hip-Hop 练舞产品：完整优化方向清单

更新日期：2026-08-12  
文档状态：**仅用于核对方向与颗粒度，尚未选择下一步，不排序、不排期。**

## 0. 这份文档怎么读

本文件把目前讨论过的方向全部放回同一张地图，但不表示要同时开发。

每个条目分为三种来源：

- **已明确**：用户直接提出，或旧项目规划已经明确记录。
- **已实现 / 正在收尾**：产品里已经存在，或本轮已经完成主体功能。
- **待确认推导**：根据原话展开的可能功能，只用于检查颗粒度，不算正式需求。

这里采用的颗粒度是：

- “练习记录”“视频识别”“元素知识页”属于一个产品方向。
- 方向下面的“编辑、回填、确认候选”等属于功能。
- IndexedDB、Supabase upsert、R2 对象替换属于实现方式，不单独算产品方向。

## 1. 项目当前状态

目前产品已经从动作展示页发展为私人练舞资料库：

- 87 个 Hip-Hop 动作元素，可搜索、筛选和播放原声片段。
- 每日随机推荐 5 个动作，可选 3 个练习。
- 练习记录包含日期、动作、歌曲、变形、地点、同伴、舞种、感受、回馈和下次重点。
- 支持上传或 Ctrl+V 粘贴练习视频。
- 支持在当前 87 个动作资料中提取视频动作候选，并补充 Hip-Hop 舞种。
- 文字和视频先保存在本机；登录后，文字同步 Supabase，视频进入私有 Cloudflare R2。
- 使用者只注册本网站账号，不需要分别注册 Supabase 或 R2。

关于此前 HTML 中的“2.1 GB”：那是视觉生成时产生的假示例，不是真实云盘用量。当前已有一条文字练习记录，没有附视频；页面也尚未实现真实 R2 容量统计。

### 2.1 已有记录的编辑

- 练习歌曲 / 舞曲。
- 今天的感受。
- 做得好的地方。
- 需要注意。
- 动作要领 / 新发现。
- 收到的回馈。
- 下次练习重点。
- 口述原文。

- 按动作、歌曲、地点、同伴或日期筛选历史记录。
- 周/月练习回顾和统计。

## 3. 练习视频与动作识别

来源：**用户明确提出上传/粘贴与提取元素、舞种；其余是旧方向和待确认展开。**

### 3.1 已实现

- [x] 上传练习视频。
- [x] 直接 Ctrl+V 粘贴视频。
- [x] 提示“复制粘贴可以提取元素和舞种”。
- [x] 根据当前动作资料库输出 2–3 个动作候选。
- [x] 将候选动作带入当前练习记录。
- [x] 当前资料库范围内补充 Hip-Hop 舞种。
- [x] 视频可在本机预览；登录后可保存至私有 R2。

### 3.2 已知边界

- 当前不是通用舞种识别，只是在 87 个 Hip-Hop 动作中做姿态匹配。
- “Hip-Hop”来自当前资料库范围，不代表模型已经准确识别所有舞种。
- 动作结果是候选，需要用户结合原视频确认。

### 3.3 待确认的优化

- 显示每个候选的置信度。
- 标出候选动作对应的视频时间点。
- 允许一键确认、纠正或移除候选。
- 保存用户纠正结果，避免以后重复纠正。
- 支持从完整视频中识别多个连续动作，而不是只取一个片段。
- 扩充 Afro、House、Locking 等其他舞种资料库。
- 自动提取歌曲信息、练习日期或视频备注。

## 4. 每日练习方法与训练流程

来源：**深圳 HZ 老师推荐方法，旧规划已明确。**

原始方法：

1. 每天练 3 个元素，系统可推荐 5 个供选择。
2. 一个元素练 4 首歌。
3. 3 个元素加 3 个变形。
4. 每次整理练习内容，但自己的练习内容不要告诉别人。
5. 每次身体最多承受 4–6 个元素。
6. 最重要的是使用自己喜欢的歌。

### 4.1 已实现

- 每天推荐 5 个元素。
- 可从中选择 3 个并带入记录。
- 每个元素可记录 4 首歌曲。
- 每个元素可记录一种变形方向和说明。
- 不选满 3 个也能记录，避免系统限制真实练习。

### 4.2 待确认的优化

- 标记某个动作“今天已练”。
- 为每首歌记录练习完成状态。
- 提醒一次不要超过身体可承受的动作数量。
- 保存自己喜欢的歌曲，之后用于推荐。
- 根据历史练习自动推荐较少练或想继续修正的动作。
- 练习计时、组数或节奏速度。

## 8. 视觉设计方向

来源：**2026-08-03 的视觉调研。尚未重新选择，不代表当前要改版。**

### 8.1 五个候选视觉方向

#### A. 纽约街头杂志 / Graffiti Zine

- 黑、旧纸白和单一高亮色。
- 粗窄标题、打字机或手写标记。
- 贴纸编号、撕纸边缘和复印颗粒。
- 文化辨识度强，但装饰过多会影响浏览效率。

#### B. 音乐编辑部 / Independent Magazine

- 大面积留白、超大编辑标题和摄影主导。
- 高级耐看，适合突出舞者和每日练习。
- 不等宽排版可能降低快速浏览 87 个动作的效率。

#### C. 街头潮流商城 / Drop Culture

- 黑白、红色或电光强调色。
- 编号、榜单、横向内容带和强按钮。
- 适合每日 5 个和推荐机制，但需要避免购物感。

#### D. Neo-Soul 社区档案 / Warm Archive

- 深棕、奶油白、橄榄绿和唱片封套色。
- 像唱片、杂志剪报或档案条目。
- 适合动作历史、人物来源和私人笔记。

#### E. 训练实验室 / Digital Practice Lab

- 深色训练界面，数字、计时和状态突出。
- 统一视频比例，筛选和练习按钮清楚。
- 使用效率高，文化个性需要其他方向补充。

### 8.2 交互优先方向

第一轮静态视觉未获得用户认可，旧规划明确后续应优先展示动态原型。

- Morphing cards。
- Shared-element transition。
- Horizontal slider。
- Scroll storytelling。
- 3D transition。
- Kinetic typography。
- 卡片滑动时连续变形。
- 元素卡片放大为全屏视频。
- 封面、标题和编号在卡片与详情之间连续过渡。
- 下一张卡片从侧面接力进入。

当前站内已有一个包含 3 个动作的滑动变形卡片原型，但没有被确认为最终交互方向。

## 10. 分享、朋友与协作

来源：**本轮关于朋友使用的讨论；具体分享产品尚未决定。**

已经明确：朋友如果使用产品，只注册网站账号，不需要自己开 Supabase 或 R2。

### 10.1 待确认的分享范围

- 整个账号完全私人，只做跨设备使用。
- 单条练习记录分享给指定朋友。

## 11. 内容素材与授权

来源：**旧规划明确。**

- 当前未取得原视频 UP 主授权，不把其视频作为公开产品的长期核心资产。
- 私人原型阶段保留来源说明。
- 公开发布前取得授权、替换素材，或只链接/嵌入原始公开视频。
- 公开资料优先使用摘要和原始链接，不擅自搬运完整视频。
- 老师本人录制或授权的视频才进入自有教学视频库。
- 清楚标注老师、原始链接、发布时间、出处和授权范围。
- 历史资料多来源交叉核对，不把推测写成事实。
- 尊重创作者删除和撤回意愿。
- 动作教学以真人示范为标准，AI 不替代基础教学。
- AI 可辅助卡片封面、粒子轨迹、动作残影、轮廓动画、转场和概念视觉。
- 不使用 AI 克隆或仿冒老师、UP 主的脸、身体和身份。
- 可邀请不同性别、体型和风格的舞者录制标准动作，补充女舞者示范。
- 授权协议需要覆盖：范围、期限、署名、剪辑、商业使用、撤回和报酬。

## 12. UI 素材 / 灵感库方向

来源：**用户刚提供的聊天记录。这个方向目前只是讨论过，尚未决定是否并入练舞产品。**

### 12.1 聊天记录重新提炼

用户描述的真实问题：

- 做 Demo 时没有自己的素材积累，经常从零开始。
- 一个方案不满意就全部推倒，一天可能重做三四次，长期工作到很晚。
- 会在小红书收藏好看的内容，但收藏并没有在下一次设计中发挥明显作用。
- 当前更想积累 UI，尤其是 App 界面。
- Senior 设计师似乎可以很快知道 Demo 应该做成什么样，自己却要想很久，缺少头绪。

对话中直接给出的思路：

- 多参考市面上流行、接受度高的产品。
- 从别人的产品中提取自己认为有用的部分。
- 将不同参考中的有用部分重新组合。
- 看得足够多以后，逐渐形成自己的想法。
- 参考和重组不是照搬。

这段对话的核心不是“再做一个收藏夹”，而是建立一种不必每次从白纸开始的 UI 工作方法。

### 12.2 可以确认的方向颗粒度

**方向名称：个人 UI 素材 / 灵感库。**

它解决的是一个完整问题：让收集过的 UI 参考在以后做 Demo 时能被找到、理解和复用。

以下可视为这个方向的基础功能层，而不是四五个新的产品方向：

- 收集 UI 参考。
- 对参考进行整理。
- 找到需要的参考。
- 理解参考哪里有用。
- 在新的 Demo 中重新组合使用。

### 12.3 待用户确认的产品化细节

下面是我根据对话推导的可能实现，并非用户原话：

- 保存 App 截图、网页截图或原始链接。
- 为素材记录产品名、页面类型和来源。
- 写下“我为什么收藏它”。
- 标记可复用部分：布局、配色、字体、导航、卡片、按钮或转场。
- 按设计任务查找：登录页、列表页、详情页、Dashboard、编辑器等。
- 做新 Demo 时，把多份参考放到同一个临时看板中对照。
- Demo 完成后记录哪些参考最终采用、哪些没有采用以及原因。
- 自动提取配色、字体或组件。
- 相似 UI 搜索和推荐。

其中前七项是相对直接的工作流；“自动提取”和“相似推荐”颗粒度更大，也更依赖 AI，不能默认算进第一版。

### 12.4 与练舞产品的关系尚未决定

可能有三种关系，需要用户之后判断：

1. 它是完全独立的个人 UI 工具，不放进练舞网站。
2. 它是练舞网站内部的一个私人素材模块，用来积累舞蹈网站和海报的视觉参考。
3. 暂时只把它当作设计练舞产品的方法，不开发成产品功能。

目前不替用户选择其中任何一种。

## 13. 同类产品调研中保留的机会点

来源：**旧调研。**

市场上已有舞步词典、教程库、课程平台和文化资料页，但“统一短视频动作卡 + 快速检索 + 每日练习 + 私人练习记录”的组合并不常见。

已记录的可借鉴点：

- STEEZY：动作名称、背景、示范和教程入口。
- Rae Studios / More Than Movement：年代、地区、创造者和文化语境。
- DanceWithCeech：按舞种与身体重点筛选，强调节奏训练。
- CLI Studios：术语小词典。
- Dancers Forum：每个动作拥有独立、可被搜索引擎索引的页面。

旧规划给出的差异化定位仍然保留：

> 一个尊重 Hip-Hop 文化来源、能快速查动作，也能每天直接开练的个人元素资料库。

## 19. 课堂分析体验与个人轨迹（2026-08-12）

## 21. 人物框与老师直拍的手动校正（下一步优化方向）

来源：**用户 2026-08-13 明确提出，尚未实施。**

当前真实问题：

- 课堂画面人物较多时，自动识别框不一定能稳定锁定目标人物。
- 用户已经确认并上传老师示范后，系统仍可能截到错误的“人物 1”。
- 老师直拍当前只截取一个较短的自动候选片段，不能覆盖用户真正想保留的完整视频时段。

下一步需求：

1. **手动锁定人物框**
   - 自动识别先提供一个初始框，不作为最终结果。
   - 用户可以直接在视频画面上拖动人物框，移动到正确人物身上。
   - 支持拖动边角缩放框的大小，以适应远近、前后排和多人遮挡场景。
   - 人物过多或自动跟踪失败时，允许用户直接新建一个手动框，不强迫继续自动识别。

2. **老师人工确认优先**
   - 用户选择“有老师”后，可从候选人物中确认老师，也可手动框选老师。
   - 一旦用户手动确认，老师直拍必须以人工选定的框为准，不再默认使用“人物 1”或覆盖人工选择。
   - 额外上传的老师示范视频使用同一套手动框选逻辑。

3. **手动调整截取时长**
   - 在老师直拍预览下提供时间轴和开始/结束两个拖动手柄。
   - 默认可以选择完整视频时长，而不只限制在当前自动生成的几秒候选片段。
   - 用户可拖动选择真正的示范起点和终点，并在保存前循环预览。
   - 保存时同时记录人物框位置、起止时间、视频来源和是否为人工确认。

4. **交互原则**
   - 自动识别负责减少操作，手动框选负责兜底和纠错。
   - 清晰显示当前采用的是“自动框”还是“人工框”。
   - 只有用户点击确认后才生成最终老师直拍，避免反复转码和无效占用存储。
